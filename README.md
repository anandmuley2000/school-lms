# School LMS

Existing LMS application with a Java 21 / Spring Boot 3 API backed by MySQL, a React + Vite admin portal, an Expo React Native app, and a Capacitor Android wrapper for the admin portal. Clients authenticate with JWT bearer tokens and role-based access.

## Features

- Admin, teacher, parent, and student dashboards.
- Student records, attendance, homework, results, fees, notifications, messages, events, bus routes, and leave requests.
- Admin account directory and role assignment. Creating a student provisions a linked STUDENT login.
- Development-only demo data and reset, OpenAPI/Swagger, and Actuator health.
- Expo app with secure token storage and a separate Capacitor Android app.

## Requirements

Java 21, MySQL 8 or compatible, Node.js 22+ and npm. Android builds additionally need the Android SDK/JDK setup expected by the Gradle wrapper.

## Local development

1. Create a local MySQL database/user. Copy `backend/.env.example` to `backend/.env` and set a local password and a unique `JWT_SECRET` of at least 32 UTF-8 bytes. Spring Boot does not load `.env` automatically, so export its values in your terminal or IDE environment.
2. Start the backend in PowerShell from the repository root:

```powershell
$env:SPRING_PROFILES_ACTIVE = "development"
.\mvnw.cmd -f backend\pom.xml spring-boot:run
```

The development profile defaults to MySQL at `localhost:3306`, database `school_lms`, user `root`, and password `tiger`; override these with `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USERNAME`, and `DB_PASSWORD`. Backend URL: `http://localhost:8080`; health: `/actuator/health`; Swagger: `/swagger-ui/index.html`.

3. Start the React admin in a second terminal:

```powershell
Set-Location admin
Copy-Item .env.example .env
npm ci
npm run dev
```

The local API base is `http://localhost:8080/api`. For access from another device during development, set the API base to the development computer's LAN address and allow the browser origin in development CORS.

4. Start the Expo app in a third terminal if needed:

```powershell
Set-Location mobile
Copy-Item .env.example .env
npm ci
npx expo start
```

For a physical phone, set `EXPO_PUBLIC_API_BASE_URL` to an API address reachable from the phone. The phone's `localhost` is the phone itself.

## Accounts

Demo credentials are for local development only: `admin@schooldemo.com` / `Admin@123`. Demo accounts and demo data are seeded only under the `development` profile. Production does not create a default administrator. Provision the production administrator through a controlled, secure process; never reuse the demo password.

When an admin adds a student, the backend creates and links a STUDENT account in one transaction and stores the password with BCrypt. Create parent and teacher accounts in the admin account directory.

## Checks

From the repository root:

```powershell
.\mvnw.cmd -f backend\pom.xml test
$env:VITE_API_BASE_URL = Read-Host "Set the real deployed HTTPS API URL ending in /api"
npm --prefix admin run build
Set-Location mobile
npm ci
npx tsc --noEmit
```

Production frontend builds require the real HTTPS backend API URL ending in `/api`; wait until the backend exists, then set that environment variable. For local frontend work use the `.env.example` file and development server. Production backend configuration uses MySQL with `ddl-auto=validate`; it does not create/update the schema. Capacitor's Android web assets are generated by `npx cap sync android` and are not committed; run sync after each build.
